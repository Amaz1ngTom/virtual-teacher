# 公开源码发布检查

## 默认离线检查

在项目根目录、现有 Web 环境执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/maintenance/run_release_checks.ps1
```

包括后端离线测试、前端静态检查/录音编码测试/构建，以及发布白名单文件扫描。
不调用云模型、TTS 或 FLOAT。不新建环境、不自动安装依赖。
可选 `-PythonExecutable <解释器路径>` 指定当前环境。

## 独立源码快照

```powershell
python scripts/maintenance/export_github_source.py --check
python scripts/maintenance/export_github_source.py
```

输出在被 Git 忽略的 `dist/github-source-时间戳/` 和同名 ZIP，
附 SHA-256 文件清单。使用明确白名单，不导出 .git 历史、个人配置、模型、教材、用户数据、
调试日志、待机视频或生成缓存；保留有来源说明的两张示例教师图片。
源目录不被删除或修改，重复运行建立新目录而不是覆盖旧包。

发布时应在这份快照里建立新的 Git 仓库，不要直接推送含个人开发历史的原仓库。
仅加入 .gitignore 无法清除已有 Git 历史。ZIP 是源码包，不是包含环境的一键运行整合包。
修改项目后应重新测试并重新导出；快照不会自动同步后续改动。

## 发布前人工确认

- [ ] 阅读 MIT 原创代码许可与 THIRD_PARTY_NOTICES.md，确认符合作者意图。
- [ ] README 的安装步骤、功能边界和性能措辞属实；未做全新安装验证需明确写出。
- [ ] 核对素材来源；不附教材正文、用户对话及来源未确认的视频。
- [ ] 人工查看导出清单；自动扫描不保证发现所有秘密。
- [ ] 若有泄露过的凭证，先轮换，不能仅删除文件。
- [ ] 选择公开作者名/联系方式、仓库名并添加脱敏截图和短演示。
- [ ] 需要外部用户稳定安装时，另行做干净环境验证；此次不声称完成该项。
- [ ] 实际上传 GitHub 前再次确认发布范围，上传不是本地整理的默认动作。

## 验证与演示建议

- 测试使用临时数据、假 LLM/TTS/Worker，不复用用户聊天作为测试存储。
- 真人麦克风的口音/噪声效果需用户实测；脚本模拟麦克风不等于准确率评测。
- 实机展示可使用现有课程缓存，避免重复调用付费 TTS。
- 需要新的端到端验证时单独确认费用与 GPU；不同机器用同样样本对比。
- FLOAT 速度统一写成“视频时长 / 推理耗时”；不能用纯推理吞吐替代用户首播等待。
